# W65C02 CPU Core

This document gives a practical overview of the CPU core used by the emulator. It focuses on the
main ideas behind instruction execution and does not require detailed knowledge of the 6502.

## Overview

The CPU is implemented as a cycle-based component. An instruction is not executed in one large
function call. Instead, it is split into the individual clock cycles needed to read operands,
calculate addresses, perform an operation, and write results.

The current core supports the 56 standard 6502 instruction mnemonics and all 151 official opcode
encodings. This includes the different addressing modes of an instruction. For example, `LDA` has
separate opcodes for immediate, zero-page, absolute, and indirect addressing.

## CPU State

The programmer-visible state consists of:

- `A`: accumulator used by arithmetic, logic, and load/store instructions
- `X` and `Y`: index registers used for indexing and data transfer
- `S`: stack pointer for the stack in memory page `$0100-$01FF`
- `PC`: program counter containing the address of the next program byte
- Processor flags: `N`, `V`, `D`, `I`, `Z`, and `C`

The implementation also uses internal registers:

- `IR`: the currently executing opcode
- `ADL` and `ADH`: low and high bytes of a temporary or effective address
- `TMP`: temporary storage used during multi-cycle operations

These internal registers make it possible to build an address over several cycles, just as the
original processor must read multi-byte values one byte at a time.

## Instruction Lifecycle

Every instruction follows the same basic sequence:

1. Read the opcode from the address in `PC`.
2. Store the opcode in `IR` and increment `PC`.
3. Decode the opcode and queue the required clock cycles.
4. Read operands and calculate the effective address when necessary.
5. Execute the operation and update registers, flags, or memory.
6. Start the next opcode fetch when no cycles remain.

The CPU stores pending work in a queue. Each queue entry represents one clock cycle and contains an
action for phase 1 (`Ph1`) and phase 2 (`Ph2`). Phase 1 normally prepares the bus address and selects
read or write mode. Phase 2 consumes read data, changes CPU state, and completes the cycle.

This design is important because instruction timing is visible behavior on a 6502. An immediate
load takes fewer cycles than an indexed memory read, and some indexed reads need an additional
cycle when they cross a memory-page boundary.

## Decoding and Shared Logic

The opcode decoder does not contain a separate full implementation for every opcode. Opcodes with
the same addressing behavior are grouped together.

For example, `ORA`, `AND`, `EOR`, `ADC`, `LDA`, `CMP`, and `SBC` can all read an operand through the
same addressing-mode code. After the operand has been loaded, the value in `IR` selects the actual
operation.

This separates two questions:

1. Where does the operand come from?
2. What should the CPU do with the operand?

As a result, page crossing, zero-page wrapping, and indirect pointer handling are implemented once
and shared by several instructions.

## Addressing Modes

The core supports the standard addressing modes required by the official instruction set:

- Implied and accumulator
- Immediate
- Zero page, zero page X, and zero page Y
- Absolute, absolute X, and absolute Y
- Indexed indirect `($nn,X)`
- Indirect indexed `($nn),Y`
- Relative addressing for conditional branches
- Indirect addressing for `JMP`

Zero-page calculations use 8-bit arithmetic. This means an address such as `$FF + X` wraps around
inside the zero page instead of continuing into page one.

Indexed absolute and indirect reads check whether the resulting address crosses a 256-byte page.
When required by the instruction, the CPU queues an additional clock cycle. Store instructions use
their fixed timing even when the target address crosses a page.

## Instruction Families

The implementation groups instructions by their general behavior:

| Family | Instructions |
| --- | --- |
| Load and store | `LDA`, `LDX`, `LDY`, `STA`, `STX`, `STY` |
| Logic | `ORA`, `AND`, `EOR`, `BIT` |
| Arithmetic and compare | `ADC`, `SBC`, `CMP`, `CPX`, `CPY` |
| Shift and modify | `ASL`, `LSR`, `ROL`, `ROR`, `INC`, `DEC` |
| Register transfer | `TAX`, `TAY`, `TSX`, `TXA`, `TXS`, `TYA` |
| Register increment/decrement | `INX`, `INY`, `DEX`, `DEY` |
| Flags | `CLC`, `SEC`, `CLI`, `SEI`, `CLV`, `CLD`, `SED` |
| Conditional branches | `BCC`, `BCS`, `BEQ`, `BMI`, `BNE`, `BPL`, `BVC`, `BVS` |
| Jumps and subroutines | `JMP`, `JSR`, `RTS` |
| Stack and interrupt control | `PHA`, `PHP`, `PLA`, `PLP`, `BRK`, `RTI` |
| Other | `NOP` |

## Processor Flags

Instructions update only the flags defined by their behavior:

- `N` is set when bit 7 of a result is set.
- `V` reports signed overflow for arithmetic and receives bit 6 for `BIT`.
- `D` enables packed-decimal arithmetic.
- `I` disables maskable interrupts.
- `Z` is set when a result is zero.
- `C` stores carry, no-borrow, or the bit shifted out by a shift/rotate instruction.

The helper used by many instructions updates `Z` and `N` together. Compare instructions do not
change the compared register; they update `C`, `Z`, and `N` as if a subtraction had been performed.

## Arithmetic

`ADC` adds the operand and the current carry to `A`. `SBC` treats a set carry as "no borrow" and a
cleared carry as an additional borrow.

Both instructions calculate carry and signed overflow. When decimal mode is active, the low and
high nibbles are corrected as packed decimal digits. Decimal `ADC` and `SBC` also add the extra
cycle used by the W65C02 behavior implemented by this core.

## Read-Modify-Write Instructions

Memory versions of `ASL`, `LSR`, `ROL`, `ROR`, `INC`, and `DEC` follow a shared sequence:

1. Calculate the target address.
2. Read the old value.
3. Calculate the new value and store it in `TMP`.
4. Complete the required intermediate cycle.
5. Write the new value back to the same address.

Accumulator versions modify `A` directly. Rotate instructions use the old carry as the incoming
bit and place the outgoing bit back into carry.

## Branches and Control Flow

Conditional branches use a signed 8-bit offset relative to the address after the operand. Their
timing depends on the result:

- Two cycles when the branch is not taken
- Three cycles when the branch is taken
- Four cycles when a taken branch also crosses a page

`JSR` stores its return address on the stack before loading the target address. `RTS` restores that
address and advances it to the next instruction. Indirect `JMP` currently reproduces the classic
NMOS 6502 page-boundary wrap behavior for a pointer ending in `$FF`.

## Stack and Software Interrupts

The stack always uses memory page one. `S` contains only the low byte of the stack address:

```text
stack address = $0100 | S
```

A push writes the value and then decrements `S`. A pull increments `S` before reading the value.
Because `S` is an 8-bit register, it naturally wraps within page one.

`BRK` behaves as a software interrupt. It pushes the return address and processor status, sets the
interrupt-disable flag, clears decimal mode, and loads a new program counter from `$FFFE/$FFFF`.
`RTI` restores the processor status and program counter from the stack.

## Current Scope

The core implements the 151 official opcode encodings of the standard 6502 instruction set.
Undocumented opcodes and additional W65C02 instructions such as `BRA`, `STZ`, `PHX`, and `PHY` are
not part of this set yet. Unknown opcodes raise an emulator exception instead of being executed.

Hardware interrupt input handling for IRQ and NMI is also outside the current instruction-set
implementation. `BRK` and `RTI` are implemented because they are official software-visible
instructions.
